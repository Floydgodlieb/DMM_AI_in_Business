# Wiki schema

The wiki is a persistent, interlinked synthesis of the source library, kept current by the assistant. It sits between the library and the people who write handbook pages: the cross-references, the contradictions and the running picture are already there when a new week's question arrives.

Read `context.md` first, as for every task. This file only says how the wiki works; it holds no copy of the reader, criteria or house style.

## Three layers

| Layer | Files | Who writes it |
|---|---|---|
| Raw | `library/sources/S-0xx.md`, `appraised.md`, `claims_en.md` | The pipeline stages (1-3). The wiki never edits these. |
| Wiki | `wiki/` | The assistant. People read it, comment, and steer. |
| Schema | `wiki/SCHEMA.md` (this file) | The team and the assistant, together, as the wiki grows. |

## The one rule

**Every fact in the wiki ends with the claim-id it rests on**, in square brackets: `... used AI in 2024 [W2-001]`. The claim block in `claims_en.md` carries the source id and the verbatim sentence, so the trace is complete.

- No claim, no fact. A source that has no claims yet may be described (what it is, who published it) but not quoted or summarised as fact. Write the gap down instead: "No claim yet on X" and list it under *Gaps* on the page.
- Never cite a claim that is superseded, FAILs verification, or comes from a `discard` source. `wiki.py lint` refuses these.
- A claim still awaiting a person check may appear in the wiki. Draft still applies its own rule (`/draft` step 3).
- Synthesis is allowed and is the point of the wiki: connecting claims, comparing them, noting what they do not say. Mark your own reasoning as such ("Taken together, ...") and keep every factual piece of it cited.
- The wiki is never a source for Draft. Draft cites `claims_en.md`; the wiki only helps find the right claims.
- Interview material never enters the wiki, except as claims a person typed into `claims_en.md`.

## Pages

All pages are markdown with front matter, and link to each other with `[[basename]]` (Obsidian style). Open `wiki/` as an Obsidian vault to browse it and see the graph.

```
---
title: <name>
type: source | topic | entity | answer | overview
summary: <one line, shown in index.md>
updated: YYYY-MM-DD
sources: S-001, S-002        # topic, entity and answer pages: the sources they draw on
---
```

| Folder | One page per | Must contain |
|---|---|---|
| `library/sources/S-0xx.md` | source in the library | *What it says* (3-6 cited sentences), *Where it fits* (links to topics and entities), the generated facts block |
| `topics/<kebab-name>.md` | idea, duty or question that recurs (e.g. `ai-act-literacy-duty`) | A lead sentence, the cited picture, *Contradictions and tensions*, *Gaps*, *Sources* |
| `entities/<kebab-name>.md` | organisation, programme or product (e.g. `cbs`, `edih`) | What it is, what the library says about or from it, links |
| `answers/<yyyy-mm-dd>-<kebab-name>.md` | question worth keeping | The question, the cited answer, the pages it drew on |
| `overview.md` | the whole wiki | The current picture in one page, with links into topics |

`index.md` is generated by `wiki.py refresh`; never edit it by hand. `log.md` is appended by `wiki.py log`; never rewrite earlier entries.

Between the lines `<!-- generated by wiki.py refresh ... -->` and `<!-- end generated -->` the script writes publisher, rating, decision and every claim with its status. Never edit inside that block.

### Contradictions

When two claims disagree, or a newer claim overtakes an older one, keep both and flag it on the topic page:

```
> [!contradiction] W4-031 vs W2-004: <what differs, in one line>
> <one or two sentences on why: different year, scope, population, or definition>
```

Labels matter here: a `case` claim (BAS World) never contradicts a `sector` claim; it is a frontier example, not the average (context.md §2).

## Operations

### Ingest (`/wiki-ingest`)
1. `python .claude/scripts/wiki.py refresh` then `status`: it lists source pages still to ingest and claims not yet used.
2. Per source: read the raw file and its claims, write *What it says* and *Where it fits*, set `summary`.
3. Update every topic and entity page the source touches (typically 3-10); create a page when a topic recurs in two or more sources. Flag contradictions. Update `overview.md` when the picture changes.
4. `wiki.py refresh`, `wiki.py lint` until 0 errors, then `wiki.py log ingest "<S-ids>" "<pages touched>"`.

### Query (`/wiki-query <question>`)
1. Read `index.md`, then the pages it points to, then the claims they cite.
2. Answer with claim-ids. Name what the library does not cover.
3. If the answer is worth keeping, file it under `answers/`, link it from the topics it uses, and log it.

### Lint (`/wiki-lint`)
1. `wiki.py lint` for the mechanical part: broken links, bad citations, orphans, numbers without a claim-id, stale index.
2. Then by reading: claims that disagree but are not flagged, topics mentioned on three or more pages without their own page, missing cross-references, overview out of step with topics.
3. List gaps as candidate search lines for `/find-sources` (line code + what to look for). Do not search yourself.
4. Fix what you can, log it.

## Log format

```
## [YYYY-MM-DD] ingest | S-043, S-044
<pages touched>
```

`grep "^## \[" wiki/log.md | tail -5` shows the last five operations.
